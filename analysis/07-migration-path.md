# 07 — Migration path

Staged route from today's `ardopcf` to [06](06-target-architecture.md), with a
working radio at every step and a named exit criterion per stage.

The ordering principle: **build the safety net before touching anything, then
change one axis at a time.**

---

## Stage 0 — Golden vectors — **done**

Built, and living in [`test/golden/`](../test/golden/README.md).

```sh
make golden          # check this build against the corpus  (~6 s)
make golden-regen    # rewrite the corpus (moves the baseline)
```

130 cases — all 22 control frames, and all 18 data frame types × even/odd ×
three fill levels — each decoded through both the standard and the `--sdft`
demodulator. 424 assertions, no audio hardware, ~6 seconds, `python3` only.
17 recordings are frozen as audio (~1.0 MiB gzipped), including degraded copies
at 20 dB and 10 dB SNR; the rest are covered by TX hashes, which cost nothing
to store.

**It is known to catch things.** The modulator was deliberately perturbed with
a realistic refactoring slip — `Sample * DriveLevel / 100` rewritten as
`Sample / 100 * DriveLevel`, changing integer truncation. All 130 TX hashes
failed and 25 quality/RS figures drifted, while **every frame still decoded
correctly**. A round-trip test alone would have passed that change in silence.
That is the argument for hashing the audio rather than only decoding it.

Two findings fell out of building it, both recorded in the corpus README:
the 8-carrier modes consume 40–50% of their Reed–Solomon budget on a *clean*
signal (`16QAM.2000.100.E`: 105–127 corrections of 256, independent of drive
level), and the two demodulators disagree on `16QAM.2000.100.E` at 20 dB SNR.

### What it deliberately does not cover

Unchanged from the original plan, and stated at the top of the corpus README so
nobody over-trusts it: `--decodewav` forces **RXO mode** and substitutes a
sample-derived clock, so the corpus covers modulation, demodulation and framing
— **not** the ARQ state machine, not timing, not turnaround. It also proves
conformance to *ardopcf*, not to ARDOP_Win; recordings from another
implementation would be strictly better evidence and remain worth acquiring.

### What existed already

`test/python/test_wav_io.py` + `ardop_parameters.py` already do the full round
trip: drive `ardopcf` with `TXFRAME` and `--writetxwav` to emit a WAV per frame
type, then feed it back through `--decodewav` and compare. It passes today for
every frame type (verified — see [01](01-signal-chain.md)). The `NOSOUND` device
name makes this run with no hardware and no real-time delay.

The harness existed. What was missing was **persistence**: it generated WAVs,
checked them, and deleted them.

`test/golden/` is a separate harness rather than an extension of that one:
`test/python/` is a working test script that is expected to change, whereas a
frozen corpus has to be self-describing and stable. It carries its own copy of
the frame tables and imports nothing from `test/python/`. (The original reason
was that `test/python/` was upstream's; post-fork the separation still holds on
the durability argument alone.)

### What was built, against the original list

| | Planned | Outcome |
|---|---|---|
| 1 | Deterministic payloads | Done — xorshift32 from a per-case seed, not `randbytes()`, so the corpus can be regenerated from a four-line spec in any language |
| 2 | Commit the corpus | Done, **hybrid**: TX hashes for all 130 cases (free), real audio only for 17 where a hash would not suffice |
| 3 | Degraded copies | Done, but **not** via `INPUTNOISE` — see below |
| 4 | Memory ARQ sequences | **Not done.** Still open |
| 5 | TX bit-exactness | Done — `tx_sha256` per case, Tier 1 |
| 6 | Record the environment | Done — version, git commit, drive level and SNR floor are in the manifest |

Two things came out differently from the plan and are worth stating.

**`INPUTNOISE` cannot produce reproducible vectors.** `srand()` is seeded from
wall-clock time (`ARDOPCommon.c:476`, `ARDOPC.c:657`), so ardopcf's own noise
injection differs every run. Noise is therefore added in Python from the same
xorshift32 stream, and the resulting `.wav.gz` is committed as the
authoritative artifact. This is the better arrangement anyway: the degraded
vector is *data*, not something regenerated by the code under test.

**The hash/audio split was not in the plan and matters.** Proving a modulator
bit-exact needs only a hash. Real audio is needed for exactly two things:
testing a receiver before its own transmitter is trustworthy, and degraded
copies, which cannot be regenerated at all. Committing audio only for those
holds the corpus to ~1.0 MiB rather than ~12 MiB — which matters because
regeneration rewrites every file and git stores a fresh blob each time.

**Still open:** item 4. Memory ARQ (`SoundInput.c:149-150`) accumulates phase
and magnitude across repeated copies of the same frame, and nothing here
exercises it — every case is decoded from a single frame in a fresh process.
Covering it needs multiple noisy copies fed to one decode session, which
`--decodewav` may or may not permit without modification. Worth doing before
Stage 3 touches the receive path.

### Known limits of this corpus

Stated at the top of the corpus README so nobody over-trusts it:

- `--decodewav` forces **RXO mode** (`ARDOPCommon.c:491`), where `CheckTimers()`,
  `TCPHostPoll()` and `MainPoll()` never run (`ARDOPC.c:690`). The corpus covers
  modulation, demodulation and framing — **not** the ARQ state machine, not
  timing, not turnaround.
- It cannot catch the timing defects in [03](03-timing-model.md), because
  `WavNow` replaces the real clock. **The corpus cannot defend Stage 2** — the
  stage that matters most.
- AWGN only: no multipath, fading, frequency offset or interference.
- It proves a rebuild matches *ardopcf*, not that ardopcf matches ARDOP_Win.
- ARQ coverage needs Stage 3's in-process two-instance test, or on-air testing.

**Exit criterion — met:** corpus committed; `make golden` verifies and
`make golden-regen` regenerates; `.github/workflows/test.yml` runs the build,
the 26 cmocka unit tests and the golden vectors. Every subsequent stage must
keep it passing.

## Stage 1 — Extract the clean layers

Lowest risk, immediate payoff. No behaviour change.

- Move `StationId`, `Locator`, `Packed6`, `log`, `wav`, `sdft`, `FFT`, `noise`
  and `lib/rockliff` into a `codec`/`util` layer with their own headers. They
  already qualify.
- **Turn `FrameInfo()` (`ARDOPC.c:739-1080`) into a table.** ~340 lines of
  `switch` become a `static const ardop_frame_spec[]` plus a lookup. Mechanical,
  verifiable by exhaustive comparison over all 256 frame types against the old
  function, and it converts the single most important normative artifact into
  data.
- Collapse `ARDOPC.h` + `ardopcommon.h`: delete the 155 duplicated externs and 88
  duplicated prototypes, and **delete the dead divergent enum copies** in
  `ardopcommon.h` ([04](04-coupling-map.md)) before an include reorder makes them
  live.
- Deduplicate the quality codec (`q = 38 + 2*(t & 0x1F)`) into one function.

**Exit:** golden vectors pass; exhaustive `FrameInfo` equivalence test passes;
one header per module; `make test` green.

## Stage 2 — Invert the clock

The highest-value change, and self-contained.

- Introduce `uint64_t t_samples`, incremented by the audio reader. Thread it
  through explicitly; delete the `Now` macro.
- Convert every deadline in the [03](03-timing-model.md) table from milliseconds
  to samples. Keep wall-clock only for log timestamps and the 10-minute
  regulatory ID.
- Replace `SoundFlush()`'s busy-wait (`ALSASound.c:1789-1797`) with a
  drain-observed completion using `snd_pcm_delay()`/`snd_pcm_avail_update()`.
  Note the commented-out earlier attempt at `ALSASound.c:1799-1830` and its
  warning that some cards misreport state — hence *drained sample count*, not
  device state, as the completion signal.
- Delete `SlowCPU` (`SoundInput.c:886-897`). It is already dead — never
  assigned, so the 480-sample branch is unreachable ([03](03-timing-model.md)).
  Removing it is provably behaviour-preserving, which makes it a good first
  exercise of the Stage 0 corpus rather than a change needing justification.
- Once TX completion is observed rather than predicted, **delete `FixTiming` and
  `-A`** — a rate mismatch is no longer a correctness problem.

**Exit:** golden vectors pass; ardopcf runs on a card that previously required
`-A`; an on-air ARQ session with a real ARDOP peer completes. Retire the
`FixTiming` error message only after the on-air test.

> This stage is where a real radio is genuinely required. It changes turnaround
> timing, which only the far end can validate.

## Stage 3 — Lift the FSM out of the DSP

- Move the `IRStoISS` turnover out of `ProcessNewSamples()`
  (`SoundInput.c:1070-1090`) into the FSM — this is the maintainer's own `TODO`
  at `ARQ.c:1759`.
- Make `ProcessNewSamples()` emit **events** instead of calling protocol code.
- Rewrite `ProcessRcvdARQFrame()` as a transition function returning actions
  ([06](06-target-architecture.md) Rule 3). The [02](02-protocol-fsm.md) table is
  the specification for this.
- Remove the `ProtocolState` reads from the demodulator (`SoundInput.c:822`,
  `:864`); the shell decides whether to feed samples in.
- Delete `txSleep()`. Turnaround delay becomes a timer action, not a sleep. This
  removes the TX-inside-TX reentrancy.
- Merge `ProtocolMode`/`ProtocolState`/`ARQState` into one state type.

**Exit:** a test that runs two `ardop_link` instances against each other
in-process through connect → data → gear-shift → BREAK/turnover → disconnect,
with no audio device and no wall-clock. **This is the first test that covers the
ARQ protocol at all** — the gap Stage 0's corpus explicitly cannot fill.

## Stage 4 — Platform behind an interface

- Define the platform interface: audio in/out, PTT, serial, sockets, wall-clock,
  files.
- Collapse the duplicated spine in `ALSASound.c` (2289 lines) and `Waveout.c`
  (1292 lines) into one portable main loop plus two thin backends.
- Fix the divergences found in [04](04-coupling-map.md): `-L`/`-R` broken on
  Linux and no-ops on Windows; `extraDelay` missing from the Windows repeat
  scheduling.
- Replace the `BOOL`/`UCHAR`/`VOID`/`HANDLE` typedefs with `<stdint.h>` types and
  a real handle abstraction — this is what produced the `lib/rawhid` build
  failure on GCC 14.
- Move `wg_send_*` out of `SoundInput.c`, `ARQ.c` and `Modulate.c`; the shell
  observes core events and updates the GUI.

**Exit:** core layers link and test with **no** ALSA, no sockets, no WebGui; both
platforms build clean at `-Wall -Wextra -Werror`; ardopcf builds on GCC 14
without `-Wno-int-conversion`.

## Stage 5 — Reassess the language

With the core pure, explicitly-stated, and covered by Stage 0 and Stage 3 tests,
the Rust question from [06](06-target-architecture.md) becomes a low-risk,
separable decision — port a module, run the vectors, keep or revert. Take it then,
with evidence, rather than now.

## Fixes worth landing independently

These do not depend on the restructure and can be taken in any order, before or
alongside Stage 1. Each is small, and each now has the Stage 0 corpus to prove
it changed nothing it should not have:

| Fix | Location | Note |
|---|---|---|
| `-L`/`-R` stereo de-interleave | `ALSASound.c:1563` | Confirmed broken; compact to `input[0..ret-1]` |
| Redundant `memcpy` loop | `ALSASound.c:1551-1554` | Loop body is `n`-invariant; runs 240× |
| TX channel uses RX flag | `ALSASound.c:1426` | `UseLeftRX` should be `UseLeftTX` |
| `rawhid` handle type | `lib/rawhid/rawhid.c:341` | Build failure on GCC 14+ |
| Unchecked `strFault` | `ALSASound.c:1863` | Capture reopen failure silently ignored |
| Oversized stack arrays | `ALSASound.c:1405`, `:1498` | 512 KB and 128 KB |
| Dead divergent enums | `ardopcommon.h:257-318` | Delete before an include reorder makes them live |
| `extraDelay` on Windows | `Waveout.c:866` | Behavioural divergence from Linux |

The first is the one to prioritise — it is a confirmed, silent, total RX failure
reachable through a documented command-line option.

## Fork housekeeping

Independent of the stages, and worth doing deliberately rather than drifting
into. This is a fork of the *code*, not of the protocol — on-air interop and the
TCP host interface still bind, which constrains two of these more than they look.

| Item | Where | Note |
|---|---|---|
| Project name | `ProductName[] = "ardopcf"` (`ARDOPC.c:5`) | **See the warning below — not a free rename** |
| Version scheme | `ProductVersion[]` (`version.h:7`), currently `1.0.4.1.3` | Diverging from upstream's numbering needs a scheme that cannot be mistaken for theirs |
| Upstream URLs in output | 10 references to `github.com/pflarue` in `src/` and `webgui/` | Startup banner (`ALSASound.c:407`, `Waveout.c:371`), `--help`, WebGui |
| `README.md` | root | Currently states the *upstream maintainer's* position on AI tools in the first person. Inaccurate on a fork and should not be left standing |
| `docs/CONTRIBUTING.md` | `docs/` | No longer binding; rewrite or remove rather than leave contradicting practice |
| Licence and attribution | `LICENSE` | Unchanged obligations — the work of Muething, Wiseman and LaRue must stay credited |

**The name is part of the host interface.** `HostInterface.c:1494` answers the
host `VERSION` command with:

```c
sprintf(cmdReply, "VERSION %s_%s", ProductName, ProductVersion);
```

so a client sees `VERSION ardopcf_1.0.4.1.3`. Anything that parses that string —
Pat, WoAD, or a script — may match on the `ardopcf` prefix. Renaming
`ProductName` is therefore a **host-interface compatibility change**, not
cosmetics, and the commitment made for this fork is that Pat and WoAD keep
working unchanged.

Before renaming, check how the host clients actually parse it. If any of them
match the prefix, the options are: keep `ProductName` as the wire identity and
carry the fork's name only in the banner and documentation; or add a separate
host command for the fork identity and leave `VERSION` alone. The first is
cheaper and is the default recommendation until evidence says otherwise.

Nothing on air carries the product name — the ID frame carries callsign and
grid square only — so the fork is invisible to other stations, which is the
desired outcome.

## Amendments made during implementation

1. **The `VERSION` reply carries this program's name and this program's build.
   The compatibility argument above is withdrawn.**

   §"The name is part of the host interface" recommended keeping
   `ardopcf_1.0.4.1.3` on the wire, and recorded a commitment that Pat and WoAD
   keep working unchanged. The reply is now `VERSION ardopb_<build>`, for
   example `VERSION ardopb_56a7de4-dirty`.

   ### Why the argument does not hold

   That section asked the right question -- *"Before renaming, check how the
   host clients actually parse it"* -- and then set a default without the
   evidence. The evidence is available without reading any client's source:

   **Host programs already meet several ARDOP implementations.** `ARDOP_Win`,
   `ardopc` and `ardopcf` report different product names and different version
   numbers. A client that could accept only the string `ardopcf` would already
   fail against most of the ecosystem it exists to serve. The compatibility the
   old value protected was therefore never at risk.

   **The cost was certain, where the risk was hypothetical.** Every log line,
   every fault report and every host program's records named a program that did
   not produce them. A tester who sends a log with `ardopcf` in it cannot show
   which software produced it. That is a real cost paid on every report, against
   a failure mode that had never been observed and was never tested.

   ### And the number is gone, not replaced

   `1.0.4.1.3` was another project's release number. Reporting it stated a fact
   about `ardopcf`, not about this software, and §"Version scheme" above
   correctly warned that a diverging scheme must not be mistaken for theirs.

   Rather than invent a second number, the reply carries the **build
   identifier**: `git describe --tags --always --dirty --match 'v*'`, the same
   value `--version` prints. There is one identity, so the string a host program
   records is the string that finds the source, and there is no number anybody
   can forget to increase.

   `--match 'v*'` matters. A plain `--tags` selects the `continuous` tag, which
   the publish job **moves** on every push to `main`, and the inherited
   `ardopcf` release tags. Neither describes a build of this software.

   ### What would change this back

   One report of a host program that fails against `ardopb_<hash>` and works
   against `ardopcf_1.0.4.1.3-b`. That is a fact worth having, and finding it
   during a test period is the reason to make this change now rather than after
   a release. `apps/README.md` and `app/ui/README.md` both ask testers which
   host software they used.
